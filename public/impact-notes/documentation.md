# Documentation
**Status:** Frontier

AI is excellent at generating documentation from code: API references, README files, inline comments, and tutorials. The gap is closing fast for technical docs. However, documentation that explains "why" decisions were made and guides users through complex workflows still benefits from human authorship.

This note records Turtleand's interpreted signals from public news sources. It is not a universal disruption score.

## Latest
- **2026-08-20**: A preprint studied 557 coding-agent sessions and 33,097 agentic pull requests. Agent-facing instructions and working notes dominated documentation interactions, no explicit documentation-based validation sequence appeared, and documentation consultation was associated with less immediate testing. The safe work shifts from generating more text toward preserving rationale and connecting claims to verification. Source: [arXiv](https://arxiv.org/abs/2608.20195)
- **2026-08-13**: The MOOSEDev preprint represented architectural decisions, constraints, lessons, rationale, provenance, and supersession as structured project memory. Its benchmark suggests this approach can outperform top-k vector retrieval on certain decision-history queries, though the reasoning engine is proprietary and a live trial was still planned. Documentation becomes versioned memory that humans and agents can inspect, not only prose generated after the code. Source: [arXiv](https://arxiv.org/abs/2608.13662)
